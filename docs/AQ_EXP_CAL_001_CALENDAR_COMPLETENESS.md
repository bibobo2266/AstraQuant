FORMAL_RESEARCH 維持無條件阻擋，未跑策略效果、未讀 E2/E3、未掃參數。

**量尺**：本項屬資料層診斷。**不報勝率／賠率／每筆期望值**，
也不得用於論斷任何元件有效或無效。

## 1. 結論

原母體 458,315 列裡，因共同日曆完整性而受影響的列數是 **0**。
四項交集 **428,102 → 428,102，增量 0**。四個 feature 的聚合全部不動，
因此不存在「哪個 feature 主導增量」的問題。

**但這個 0 很脆。** 條件化敏感度顯示：只要 E1 內有**任何一天**其實是真的交易日
而資料裡整天沒有，四項交集就會掉 **34,254 列（−8.0%）**，由 MA120 主導。
而目前有 **104 個 E1 平日無法分類**，依 fail-closed 全部標 UNKNOWN。
細節見 §5。

## 2. 缺陷是什麼

producer 沒有正典交易日曆這個概念。它的共同日曆就是**每檔自己的列序**：

```
common_row_ordinal = 每檔 tradability 列的 cumcount
MA120: common_row_ordinal >= 120 且 最近 120 個共同列裡有 120 個有效收盤
N60  : common_row_ordinal >= 62  且 最近 62 個共同列裡有 62 個有效收盤
```

它依賴一個未被檢查的前提：**每檔在其活躍區間內，每個正典 session 都有一列**，
缺值以 null 列保留、不整列消失。前提成立時 `common_row_ordinal` 才真的等於
共同 session 位置；不成立時，120 列的視窗會悄悄橫跨超過 120 個交易日。

本輪就是去驗這個前提。

## 3. 量測方法與口徑

與 ATR／幾何兩輪同一口徑：固定 revision 的 producer 重建 panel，
核對 **458,315 列 / 1,394 檔**後，在原母體與同一時間範圍內判定。

正典日曆定義：**某日只要有任一檔 `observed_trade = True`，該日即為一個 session。**
這是資料自身可得的唯一定義（repo 內沒有外部台股交易日曆）。

| 項目 | 值 |
| --- | --- |
| 全 panel 列數 | 2,427,931 |
| 正典 session（2015 暖機～2021） | 1,712 |
| E1 內 session | 1,468 |
| session 範圍 | 2015-01-05 ～ 2021-12-30 |
| panel 出現過但無人成交的日期 | 0 |

## 4. 四項判定結果

| 判定項 | 結果 |
| --- | --- |
| 重複 `(date, stock_id)` | **0** |
| 每檔活躍區間內的缺列 | **0**（1,604 檔全數檢查） |
| 列數多於 session 的檔數 | **0** |
| raw 有、tradability 無 → 被靜默丟棄的鍵 | **0** |
| tradability 有、raw 無 → `DERIVED_MISSING_ROW` | 6,996 |
| 其中落在原母體內 | **0** |

兩個要分開看的點：

- **tradability 是 raw 的超集。** 6,996 列是 tradability 有、raw 沒有的鍵，
  producer 把它們保留成 `DERIVED_MISSING_ROW`、`close` 為 null。
  這**正是**「缺值列以 null 保留」的正確行為，不是缺陷——它們仍佔住
  `common_row_ordinal` 的位置，只是不計入 `ma_valid_count`。
  且 0 列落在母體內（`close` 為 null → `current_valid` 為 False）。
- **反方向是 0。** 沒有任何 raw 鍵因為 tradability 缺列而被整列丟掉。
  若這個數字不是 0，那些列會連成為候選的機會都沒有，而且完全看不見。

所以 producer 依賴的前提在這份固定來源上**成立**，`common_row_ordinal`
確實等於共同 session 位置，MA120／N60 的視窗沒有被扭曲。

## 5. UNKNOWN：104 個無法分類的平日（fail-closed）

E1 期間有 **104 個平日不是 session**。repo 內沒有外部台股交易日曆，
**無法判定它們是國定假日還是真的缺了一個 session**，依驗收標準第 3 點
一律標 **UNKNOWN**，不以推估填補。

| 年 | 非 session 平日 | 當年 session |
| --- | --- | --- |
| 2016 | 19 | 244 |
| 2017 | 17 | 246 |
| 2018 | 16 | 247 |
| 2019 | 19 | 242 |
| 2020 | 17 | 245 |
| 2021 | 16 | 244 |

每年 16～19 天，與台股國定假日的天數同量級；58 個連續段、最長 5 天、
29 個孤立單日，形狀也像假期。**但「一致」不等於「已驗證」**，仍是 UNKNOWN。

這裡有一個無法自我修復的盲點要講明：正典日曆是由資料自身定義的
（有人成交即為 session）。**整個市場同時缺一天，在這個定義下不可見**——
那天就只是「沒有人成交」，和國定假日長得一模一樣。
要分開這兩者，必須引入外部交易日曆，那不在本輪範圍。

## 6. 什麼條件下會開始影響四項交集

驗收標準第 5 點要的就是這個。不用推論，直接模擬。

**方法**：挑一個 E1 中段、無法分類的平日（`2018-12-31`），
為該期間所有在市個股插入一列空值（`observed_trade = False`、OHLC 為 null，
即「這天其實有開市，但資料整天缺」），重跑 `add_universe` 與 `add_c_states`，
與凍結結果比對。插入 1,446 列。

| | 修正前 | 補回一天後 | 變動 |
| --- | --- | --- | --- |
| 母體列數 | 458,315 | 458,315 | 0 |
| **四項交集** | **428,102** | **393,848** | **−34,254（−8.0%）** |
| MA120 numeric | 428,102 | 393,848 | −34,254 |
| N60 numeric | 438,344 | 420,537 | −17,807 |
| ATR14 numeric | 457,916 | 457,916 | 0 |
| LOW20 numeric | 457,813 | 457,813 | 0 |

**主導 feature 是 MA120。** 機制：MA120 的視窗是對每檔 120 個共同列滾動，
且要求視窗內有 120 個有效收盤。補回一列空值會把一個真實列擠出視窗，
`ma_valid_count` 由 120 降為 119，於是該缺日之後 120 個共同列的範圍內，
原本可算的列全部轉為 `INPUT_MISSING_OR_SUSPENDED_IN_120_COMMON_ROWS`。
ATR14 與 LOW20 用的是 `valid_bar_ordinal`（只數有效 bar，空值列不計），
所以完全不動。

三件要讀對的事：

1. **方向是變少，不是變多。** 補回缺日不會讓更多列可算，只會讓更少。
2. **量級是數萬列，不是數十列。** 和 ATR 那輪的 17 筆、幾何那輪的 0 列
   完全不同量級。日曆完整性是三項缺陷裡唯一有這種放大效應的。
3. **一天就這樣了。** 本輪只模擬單一日期，沒有窮舉 104 天的組合；
   多天的效果不是線性相加（視窗會重疊），但不會更小。

所以結論的正確說法是：
**目前量到 0，條件是那 104 天全部都不是真的 session。
這個條件未被驗證，只是未被推翻。**

## 7. 這輪缺什麼

- **缺外部交易日曆。** 這是唯一能把 104 天從 UNKNOWN 移出去的東西。
  在它進來之前，「日曆完整性 = 0 列受影響」這個結論帶著一個未驗證前提。
  解法：引入一份獨立的台股交易日曆（證交所行事曆或任一不同來源的
  日期序列），把 104 天逐日判定成「假日」或「缺 session」。那是資料端的工作。
- **真實資料接上後會先動的數字**：`ma_valid_count` 不足而落在
  `INPUT_MISSING_OR_SUSPENDED_IN_120_COMMON_ROWS` 的列數（目前 28,451），
  以及跟著它走的四項交集 428,102。ATR14 與 LOW20 的 numeric 不會因此動。
- **不是本輪能回答的**：這 34,254 列的差異會不會改變任何策略結論。
  那要等 FORMAL_RESEARCH 解除、真實效果跑過才知道，本輪不碰。

## 8. 與既有結論的關係

**不矛盾。** PR #8 把日曆完整性列為未量化缺陷，本輪把它量成 0 並附上條件化敏感度，
沒有推翻任何既有結論。三項缺陷各自獨立，**不相加**：
ATR14 暖機 17 筆（AQ-EXP-ATR-001）、OHLC 幾何 0 列（AQ-EXP-GEOM-001）、
日曆完整性 0 列（本輪）。
